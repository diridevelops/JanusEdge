# Quickstart: Backtest Candle Replay

This guide describes validation to run after implementation. It was not executed during planning because this task generated design artifacts only.

## Prerequisites

- Python 3.12 and uv.
- Node.js 20 or later and npm.
- Docker Compose for MongoDB and MinIO, or equivalent local services.
- A configured JanusEdge environment and an authenticated user.
- Network access to the supported-instrument catalog and historical downloads when using Dukascopy. Manual import can use configured Settings instruments and local HistData CSV files.

## Start the application

From the repository root, start supporting services:

~~~powershell
docker compose up mongo minio -d
~~~

Start the backend:

~~~powershell
cd backend
uv sync
uv run flask run --port 5000
~~~

In a second terminal, start the durable preparation worker. It uses the same backend environment and MongoDB/MinIO services as the API:

~~~powershell
cd backend
uv run python -m app.backtests.worker
~~~

In a third terminal, start the frontend:

~~~powershell
cd frontend
npm ci
npm run dev
~~~

Alternatively, run the full stack with Docker Compose according to the repository README; the `backtest-worker` service must start separately from the API service.

## End-to-end validation scenarios

1. Sign in and switch to Backtest mode. Confirm Real trade, account, import, and report data do not appear in Backtest; return to Real mode and confirm the existing Real behavior remains available.
2. Confirm the instrument selector is populated from `GET /api/backtest/instruments`. Create a run with one listed instrument and an inclusive display-timezone date range within one calendar year; confirm a code outside the current downloader catalog is rejected without creating a run or account. Confirm the run list shows a progress stage and a percentage when measurable (otherwise indeterminate progress), and that the generated Backtest account identifies the instrument and range. Check the February 29 boundary rule.
3. Use ranges with fully empty dates, partial gaps, all-no-data, and provider failure. Confirm gap summaries do not introduce synthetic candles; no-data/failure results remain dismissible on the run-list page after the run/account are deleted and offer the specified next action.
4. Use a range with available candles. Confirm the ready run has coverage and gap summaries and a metadata-only manifest. Create another overlapping run and verify cached UTC dates, including known-empty dates, are reused. Reopen the first run and verify its pinned references remain stable after later cache fills.
5. Open a newly ready run. Confirm its workspace initializes to exactly one 1m chart pane, persists a stable chart id, and restores after reload. Confirm the compact, chart-styled timeframe dropdown is overlaid at the upper-left inside the plot and its standard presets appear before Custom. Select Custom; confirm a popup opens, enter a valid whole-minute interval, and confirm that interval (such as 7m) appears directly in the dropdown and persists after reload. Confirm invalid values show an error without replacing the last valid interval. Add another chart with the tab-row `+` button and confirm it is created and activated in the focused tab group; reorder tabs, move one to another group, drag it to a pane edge to create horizontal and vertical splits, resize the split panes, and close tabs while retaining at least one chart. Confirm no separate toolbar/instruction row or redundant chart header is shown. Confirm reload restores the full layout tree, split sizes/orientation, tab order, active tabs, chart ids, and selected intervals. Confirm CandleKit ReplayControls drive the one shared replay cursor for every panel. At 5m or another higher interval, step through source candles and verify the active bar updates from only the candles already replayed. Step backward and confirm later candles disappear.
6. Play at 1x, 2x, 5x, 15x, and 30x. Confirm each rate processes that number of one-minute source candles per second regardless of chart interval. Step forward and backward at multiple speeds; confirm each step processes the selected count, clamps to the replay bounds, and processes all intervening simulation candles. Seek to a gap and beyond the final candle; confirm the specified next-candle/completion behavior and that seeking pauses playback.
7. Test workspace migration and concurrency. For a run with legacy flat chart-tab records but no workspace document, confirm first open migrates them into visible sibling panes in saved order and preserves every id and interval; with no legacy records, confirm it creates one 1m pane. Confirm initialization is saved before workspace edits are enabled. Open the same run in two sessions, save a layout in the first, then attempt a stale save in the second; confirm the stale write returns 409 and does not overwrite the first. Confirm the second session retains its local draft and offers loading the remote layout or explicitly reapplying the draft against the latest revision. Add panels with different intervals and confirm replay position is shared and cannot be disabled. Confirm crosshair synchronization is enabled without a Chart sync section; when a target has no candle at the exact crosshair time, confirm it uses the nearest prior available candle (or no crosshair when none exists). Pan and zoom one pane and confirm other panes keep their own ranges. Move a panel while a drawing save is pending and confirm the save is flushed and replay/crosshair subscriptions are not duplicated.
8. Create, move, edit, and delete drawings. Navigate away and reopen the run; confirm drawings restore for the same user, run, and interval. Rewind and confirm the pinned CandleKit artifact's replay-aware visibility behavior; if absent, confirm drawings with any future anchor are hidden until all anchors are reached again. Under the fallback, also confirm a later-created drawing anchored entirely in the past remains visible after rewind. Open the run as another user and confirm the saved drawings are not visible.
9. Toggle JanusEdge light/dark mode. Confirm CandleKit canvas, drawing toolbar, replay controls, chart tabs, and the in-chart timeframe selector use JanusEdge colors, borders, and button styles.
10. Confirm the existing Real TradeDetail chart still shows its candlesticks, execution markers, average-entry/exit lines, interval selector, and light/dark colors after the Lightweight Charts 5.x compatibility update.
11. Exercise interrupted preparation and retry. Confirm retry reuses the same job/run/account and resumes after the latest completed UTC-date checkpoint; only an incomplete date may be fetched again. Restart the API backend while a run is preparing and confirm the separate worker continues. Restart the worker and confirm its expired lease is reclaimed from the last checkpoint. Failed/no-data run records and jobs are removed while the user-scoped preparation result remains dismissible.
12. While a run is preparing, confirm the run list refreshes progress every five seconds. During confirmed deletion, confirm the pending-deletion status refreshes too; polling stops only after the list has no preparing or deleting runs.
13. Confirm each chart pane initially snaps to the latest candle available at the saved replay cursor. Play and step forward/backward while following; verify the latest revealed candle stays at the right edge, including after a backward seek. Pan one pane backward and forward away from the latest candle; verify replay updates do not move its viewport and a lower-right return button appears. Confirm this does not change other panes. Select the button, double-click the time axis, or manually pan back to the latest edge; each action must restore follow and hide the button. Pan forward into future space and confirm follow reactivates when replay naturally catches up to the live edge. On a higher-timeframe chart, update the active bar with another source candle and confirm the horizontal range does not jump when no new chart bar is added.
14. In a test fixture, associate one or more Backtest trades with a run's dedicated account. Open the run list and select Delete; verify the confirmation identifies the run/account and warns that linked trades will be permanently removed. Cancel and confirm all resources remain. Confirm deletion and verify a 202 response is shown only as pending cleanup; the run is non-playable while pending and may be hidden from Backtest views. After completion, inspect storage and assert the run/deletion marker, account, linked trade documents and trade-owned dependent records/files, preparation/recovery jobs, replay cursor, chart layout, and drawings are physically absent. Confirm shared Dukascopy cache and manual dataset revisions remain available and no per-run candle prefix is deleted. Repeat with a preparing run while the worker holds a lease and with a worker restart during cleanup; it must never become ready, cleanup must resume, and another run plus all Real records must remain unchanged. Confirm another user's request for the same run id receives the standard not-found response.
15. Set `warmup_days` to 0 and to a positive value for both Dukascopy and Manual import. Verify the context boundary uses the configured timezone for Dukascopy and fixed UTC−5 without DST for HistData, while requested dates, one-year validation, account label, and replay-period coverage remain unchanged. With complete, partial, and empty warm-up ranges, verify the run manifest resolves available earlier candles as chart history; incomplete warm-up does not block readiness if selected-period data exists. On first open, verify the saved cursor, replay controls, progress, and completion bounds start within the selected replay period, not in warm-up. Step backward at the initial cursor and seek to a pre-start timestamp; both must remain at the first eligible replay candle. Finally verify a replay period with no candles is still reported as no-data even when warm-up candles exist, and no later replay-period candle appears before the cursor reaches it.
16. In Dukascopy New Run, confirm manual date selection remains the default and still submits the existing instrument/date/timezone request. Choose Random period and each duration (1, 3, 6, and 12 months); confirm start/end controls are disabled and omitted from the request. Submit with a configured display timezone and confirm the accepted run shows its instrument and selection status, with null dates/account. Verify the captured cutoff is yesterday in that timezone and remains unchanged after worker restart. With deterministic worker randomness, verify years and candidate dates are sampled without replacement, no year probes more than ten dates, a later probe can resolve the run, and the inclusive end obeys calendar clamping for month-end and leap-day starts. Include spring-forward and fall-back local days; confirm the probe reads all overlapping UTC dates and counts only candles inside the local day. Confirm no candidate's computed period ends after the captured cutoff. Verify provider errors create failure notices rather than empty-day attempts. Exhaust all eligible years with empty probes and confirm the dismissible result names the instrument and duration and leaves no run, job, or account. Delete a selecting run before and during a probe and confirm no account is created. After a successful hit, confirm exactly one account gets the resolved date label and the worker continues through warm-up, selected-period coverage, gaps, no-data, source-manifest, and ready-state behavior.
17. In New Run, confirm Blind mode is unchecked by default. Check it and verify the form forces random period selection, prevents switching to manual while checked, preserves the selected duration, and omits date inputs; uncheck it and verify manual/random selection is unlocked. Confirm requests without `blind_mode` retain their existing manual and random shapes and a blind request includes `blind_mode: true`. For a blind run, inspect every run-list state, detail, coverage, notice, deletion confirmation, and account selector; none may render the complete selected dates, and the account label must show instrument plus “blind” without dates. With controlled candles, verify the reference is the open of the first available replay-period candle (shown as 100), excluding warm-up; all OHLC, price labels, crosshair values, and drawings use that reference across timeframes, seek, and reload. Confirm intraday labels show configured-timezone clock time and date ticks, crosshair labels, and the current replay timestamp show only configured-timezone weekday/time, including across DST. A zero/non-finite reference must fail clearly before readiness; a negative reference must follow the formula and reverse direction while keeping transformed candle high/low ordered. Enter blind order prices on the normalized display scale and verify the API maps them back to canonical prices before price-side validation, including when the reference is negative. Inspect the API response to confirm it retains canonical raw values, as API redaction is out of scope. Once a blind-run position is fully closed, confirm Journal shows only weekday/time and normalized entry/exit values, with no complete date or raw price.
18. On a ready run with known candles, submit a market order after candle N. Confirm it remains pending through N and fills exactly at the open of the next available unrevealed one-minute candle, including when there are missing timestamp gaps; no synthetic candle is introduced. Verify neither N nor the fill candle's high/low/close changes the market fill. At the final candle, reject an unfillable new market order.
19. Submit limit entries and verify activation begins no earlier than the next available unrevealed candle. Use controlled wick-touch, gap-only, opening-through-then-wick-touch, and non-touch candles. A gap-only candle whose high-low range stays entirely beyond the limit must leave the order pending; an opening-through candle whose range later reaches the limit must fill at exactly the submitted price. Configured spread/slippage/commission are accounted separately. Verify every submitted entry requires both stop-loss and take-profit, both must be on the correct side, and missing/wrong-side/malformed prices reject without creating orders/fills. Verify quantity is always in 0.001 increments and the minimum is 0.001, with pair-specific pip/precision/contract metadata frozen into the run. Confirm pending entries can be canceled once and filled entries cannot be canceled as pending.
20. Verify each filled position has both a stop-loss and take-profit. The fill candle's range cannot trigger its new bracket; the following available candle can. For same-candle OCO ambiguity, confirm the stop wins. A take-profit limit fills exactly at its configured target only when an eligible candle's high-low range reaches it; an opening gap alone without range touch does not fill it. Configured costs are recorded separately. Exercise scale-ins, partial exits, and reversals: a same-direction fill joins the oldest open position on the instrument, updates weighted entry and combined size/cost/risk, retains the existing stop/target, and adds a separate execution; opposing fills reduce oldest positions FIFO, adjust or cancel both linked protections, and any excess opens a separately protected position. If a position closes before a pending same-direction entry fills, verify the entry starts a new position using its own bracket. Manually close a position and confirm it exits at the current revealed cursor candle close with configured costs, does not advance the cursor, and cancels its linked stop and target in the same committed operation. Confirm open positions/work orders appear in Backtest but not as closed Journal trades or closed-only analytics.
21. Set spread, slippage, and commission to zero and verify gross equals net. Then configure nonzero costs and verify half-spread per side, adverse slippage, and USD commission per lot per side on entry/exit. Change the profile between fills and confirm existing fills retain their recorded profile revision and amounts while later fills use the new values. Reject negative/non-finite settings.
22. For USD-quoted and non-USD-quoted forex pairs, verify native P&L remains in quote currency and USD P&L/risk uses USD per quote-unit at the relevant entry/exit time. Use changing conversion candles to prove each exit uses the latest completed immutable conversion candle no later than its event time. Confirm direct/inverse conversion selection and fail-closed behavior when data is missing; never accept a non-USD fill with a silently assumed rate of 1 or an unrelated latest scalar. Confirm the fully closed Trade is created exactly once under the selected run's Backtest account and existing Backtest Journal/analytics surfaces use its converted result.
23. Submit an order concurrently with replay advancement and retry requests after simulating a lost response. Confirm CAS allows one operation order, stale revisions return 409, the same operation id returns the same result, a different request with a reused id conflicts, and no duplicate fills/trades appear. Restart the API/worker with a pending operation and confirm it resumes from its journal and readers see only effects through the committed sequence. Confirm workspace/drawing writes and another user's requests cannot mutate or inspect the run's simulation state.
24. After accepting an order, try backward step/seek and confirm the API rejects it until explicit reset. Confirm pre-order backward navigation still works. Then confirm reset requires explicit confirmation, is idempotent/recoverable, removes only that run's simulation entities and closed trades, restores the cursor to the first eligible candle, increments the generation, unlocks backward navigation, and preserves costs. Repeat reset from a complete run.
25. Advance to the last available replay-period candle with working entries and open positions. Confirm the final candle's eligible fills/exits process, remaining pending entry orders cancel, open positions close at final close with costs, closed trades persist once, and status becomes `complete`. Verify complete runs remain inspectable with analytics, reject orders/cursor movement/cost updates, can be reset, and can be permanently deleted. Delete after reset and before reset; assert all run simulation records and closed Trades/dependent records are physically purged while another Backtest run and all Real records remain intact.
26. Create a run and verify the initial-balance field defaults to USD 10,000 and Risk% defaults to 1%; submit alternate positive values and confirm they persist with the run/account. Open its right-side order panel and verify the auto-size checkbox is checked by default. With known instrument metadata, FX rates, costs, entry, and stop prices, verify the USD risk budget is current balance × Risk% / 100, and the initial stop distance converts that budget to pips using one standard lot's USD pip value and the latest completed as-of quote conversion. Verify auto-sizing calculates lots from the selected stop distance, rounds down to 0.001, and refuses to submit if the minimum lot would exceed budget. Uncheck auto-size and verify a manual-lot field becomes available while projected dollar risk and risk percent remain visible. Close all or part of a position and verify the committed net cash effect of fills updates current balance, with each execution cost included once, while unrealized P&L does not; reset the run and verify current balance returns to the configured initial balance without changing its run settings.
27. Verify the entry panel collapses and expands at the right of the chart section and offers Market and Limit with long/short direction. Selecting either displays a temporary bracket overlay on the active chart with entry, both risk-derived protective levels, shading, RR, quantity, risk, and Place order/Cancel controls; initial stop pips equal the current USD risk budget divided by the instrument's USD pip value for one standard lot, and initial target distance equals the initial stop distance (1R). Canceling leaves no saved user drawing or simulation order. For Limit, drag the complete bracket and confirm entry, stop, and target move together while preserving offsets, then move stop and target independently. For Market, confirm entry remains fixed at the current revealed candle close while both protective levels move independently, then confirm actual fill still occurs at the next available candle open. Use a controlled opening gap to verify projected risk is based on the preview reference and actual initial risk is recomputed from the fill price and event-time conversion. Verify short drawing levels reverse long's orientation and blind-run levels use normalized prices.
28. After an entry fills, independently move only its stop-loss, only its take-profit, and then both. Verify each changed level becomes active no earlier than the next unrevealed candle and cannot trigger from previously revealed OHLC. Confirm the position's original initial-risk amount and R-multiple basis remain unchanged. Moving the stop creates or reuses one user `stop-moved` tag in General and associates it with the position; repeat the move/retry and confirm the tag is not duplicated. Close the position and verify the Journal Trade contains that tag. Moving only take-profit must not create the tag. Verify the API rejects changes for a closed position and rejects a level already crossed by the current revealed close.
29. After fills create two open positions, verify each appears on every chart pane with its own fixed entry line/price label, remaining quantity, unrealized USD P&L marked to the latest revealed close before hypothetical exit costs, and independently movable stop-loss/take-profit lines/price labels. Confirm P&L uses the run's frozen instrument metadata and an as-of quote-to-USD rate, is display-only, and does not change current balance or closed-trade analytics. Confirm these indicators return after navigation/reload from simulation state and never appear as saved user drawings. Move one position's protection and verify the sibling remains unchanged. Select BE and confirm only that position's stop is set to its exact entry under the normal protection rules; if the current close has crossed that entry, BE is unavailable. Select X and confirm only that position closes at the current revealed candle close without advancing replay, both linked OCO orders cancel in the same operation, and the sibling remains open with its indicators and controls. Repeat with overlapping price levels and in Blind mode; all labels must remain independently actionable and use normalized prices.
30. Switch New Run to Manual import and select a configured Settings instrument. Confirm the existing common fields/layout remain, cached coverage appears, and the form accepts an existing dataset without a new upload. Upload HistData M1 CSVs and confirm the preview shows the file's available date range before submission. Verify headerless semicolon bid OHLCV parsing, fixed UTC−5 interpretation without DST, user-confirmed overlap replacement, timestamp union, and immutable older run revisions. Confirm date controls include only candle-bearing imported dates, random selection uses imported dates and the full span when duration is too long, warm-up uses earlier imported bars, quote-to-USD fallback appears only for non-USD quotes, and manual account label has `-manual`.
31. Import a new CSV for timestamps already cached. Before confirmation, cancel and verify the active revision is unchanged. Confirm the merge prompt identifies affected dates and explains that conflicts will be replaced; continue and verify only the active dataset becomes a new merged revision while prior run manifests retain their original revision.
32. Remove one or more Dukascopy cache objects for a ready run, then reopen it. Verify the page lists each affected instrument/date and offers recovery without making a request automatically. Choose recovery; confirm only missing references are fetched, progress is visible, failures can be retried, saved simulation state survives, the cursor maps to the latest candle at/before its saved time, and the changed-history warning can be dismissed. For a manual run, verify recovery instead requires an equivalent original CSV upload and rejects different data.
33. Export Settings data and inspect the ZIP manifest: verify format 1.1 includes ready/complete Backtest state, committed simulation/account/trade/execution links, workspace/tabs/drawings, and no candle bytes/cache objects/source object keys or unfinished worker jobs. Restore to an empty destination, confirm run links and missing-data prompts, then import the same ZIP again and verify run and linked record counts are reused rather than duplicated. Confirm a 1.0 archive remains accepted and imported market-data backups still work.
34. Open a closed Backtest trade linked to a run. Verify the chart reads that run's pinned source, supports 1m/5m/15m/1h bars, shows no candle later than furthest replay progress (including after rewind), and aggregates only bounded one-minute data with a partial last bucket where needed. Verify non-Backtest trade chart source remains unchanged. Check execution prices follow Settings precision and buy/sell markers use direction-appropriate colors.
35. On replay, confirm cursor timestamps use the configured timezone and format `Mon Sep 21 2026, time`. Verify position overlays show side, compact lot precision, weighted entry, and P&L points before dollar P&L, with clear BE and close buttons. Use the stop/target handle and verify the cursor changes to a vertical up/down resize indicator.
36. With the page focused outside editable controls, verify ArrowLeft steps backward and ArrowRight steps forward by the selected speed's candle count (one candle at 1x), and Space toggles play/pause. Confirm shortcuts do not run while typing, with modifier keys, or on repeated keydown events. Verify the compact segmented transport uses accessible icon buttons without emoji and keeps manual step-forward available whenever navigation is permitted.
37. Search the Backtest instrument picker with `EURUSD` and verify it matches `EUR-USD`; search `AAPL` and verify it matches `AAPL.US-USD`. Confirm case and dots/dashes/slashes/spaces are ignored, typos and out-of-order characters do not match, selection remains the canonical instrument, keyboard arrows/Enter/Escape work, and source order is preserved. In Settings, search by pair, base asset, and quote currency; verify counts, ordering, and pagination reset after the query changes.
38. Create a manual trade using a Settings-mapped alias such as `EUR/USD` for canonical `EUR-USD`. Verify saved symbol/raw alias, mapped sizing and price rules, native quote-currency P&L, and USD conversion metadata. Exercise USD identity, direct, inverse, configured multi-leg route, unit scaling, event-time selection, refresh on symbol/exit-time edits, a manually corrected fallback, and rejection with neither eligible history nor override. Confirm the lookup uses only completed bars at or before exit time and searches the event UTC date plus the preceding seven dates. Confirm legacy Forex and futures submissions still work.
39. In the position overlay, verify the label order is side, remaining lots with increment-appropriate precision, weighted entry, and P&L in instrument units; the P&L title tooltip reports USD unrealized P&L or that it is unavailable. Confirm BE and X have clear button styling and accessible names, entry stays fixed, and stop/target handles show the vertical-resize cursor.

## Automated checks

Run from the backend directory:

~~~powershell
uv run pytest
~~~

Run from the frontend directory:

~~~powershell
npm test
npm run lint
npm run build
~~~

The frontend build confirms the locked CandleKit and Lightweight Charts types resolve together. Browser validation is still needed for the full UI scenarios, including random selection controls, drawing persistence, cursor-bounded replay, multi-interval synchronization, follow/detach behavior, and visual styling. Focused automated tests should control worker randomness and provider responses for duration boundaries, cutoff calculation, timezone/DST day filtering, ten-probe limits, exhaustion, provider failures, restart recovery, and deletion fencing.
