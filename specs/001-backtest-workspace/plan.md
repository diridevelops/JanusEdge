# Implementation Plan: Backtest Candle Replay

**Branch**: feature/backtester (Spec Kit feature slug: 001-backtest-workspace) | **Date**: 2026-09-30 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification plus the user’s planning direction: use CandleKit for Backtest charting, replay, synchronization, and drawing state; use CandleKit’s React components and style them to match JanusEdge. Use a durable preparation worker, the pinned downloader’s supported-instrument catalog, five-second run-list polling, a persisted first-candle cursor at readiness, and CandleKit ReplayControls with only a speed-selector wrapper if needed. Add per-pane follow mode that keeps the chart at the latest replay-revealed candle until the user navigates away, with a return-to-latest control. Add confirmed permanent deletion for a run, its dedicated account, and all associated trades. Add a durable random-period selection phase with 1, 3, 6, and 12 calendar-month durations and bounded, recoverable candle probing. Add optional Blind mode, which forces random selection and masks dates and raw prices in rendered Backtest views while leaving API data intact. Include simulated orders with required stop and target levels, a collapsible chart-side entry panel and draggable bracket preview, an initial USD balance of $10,000, 1% default risk per entry with an order-panel auto-sizing toggle, filled-position chart indicators with independent protection, breakeven, and exit controls, manual position closure, filled-position chart indicators with independent stop/target, BE-to-entry, and X-close controls, next-available-candle market entries, costs, FX conversion, reset, and completed-run handling.

## Summary

Add the Backtest workspace described in the feature specification, with one immutable Dukascopy one-minute candle snapshot per run that includes whatever history is available in the calendar month before the selected replay period, one shared replay cursor, and a persisted dockable chart workspace per run. New runs can retain manual dates or ask a durable worker to select a random start date with candles for a 1, 3, 6, or 12 calendar-month period. Manual dates remain unchanged; random runs stay in `selecting_period` without dates or an account until a candidate passes its candle probe. After selection, the resolved dates define the replay period, playback begins at its first available candle, and pre-start candles remain historical chart context only. New runs start with one 1m chart pane. CandleKit is the required chart and interaction layer: its React ChartView, ReplayControls, DrawingToolbar, and workspace adapter host the charts and controls; its replay and sync engines provide the replay and chart-interaction mechanisms. JanusEdge remains authoritative for run data, saved replay position, workspace layout and chart-panel configuration, user-scoped drawing persistence, random-selection checkpoints, and run deletion state.

The integration must preserve the no-look-ahead rule. CandleKit’s replay source reads the run’s one-minute snapshot, and a JanusEdge adapter aggregates only the source candles exposed through the current replay cursor into each chart panel’s selected interval. Simulation actions and candle advancement share one ordered, durable run-level operation gate. Market entries accepted at candle N cannot read N’s price action and fill at the open of the next available unrevealed one-minute candle. The collapsible right-side entry panel previews mandatory stop and target levels on the active chart; the preview is transient, with grouped movement for limit brackets, a close-anchored market entry, and independent protection-level dragging. Once filled, each open position is represented by its own run-wide chart indicators for the fixed entry and active stop/target, with independently scoped stop/target dragging, BE-to-entry, and X-close controls; these indicators derive from committed simulation state and do not enter saved user drawings. Manual close and X use the currently revealed candle close and cancel both linked protection orders in the same committed operation. A $10,000 default initial balance and 1% default risk configure the auto-sizing checkbox, enabled by default; manual lot sizing remains available when disabled. Intrabar exits, protection, spread, slippage, and commission follow the spec’s deterministic rules. Open positions remain in simulation projections; only fully closed trades are published to the dedicated Backtest account and existing closed-trade analytics. Users can create, reorder, move, split, resize, and close chart tabs. Crosshair synchronization passes through CandleKit’s SyncEngine, with an adapter that translates between logical bar indexes and UTC timestamps so panels at different timeframes remain aligned; horizontal panning and zooming remain local to each pane. A compact timeframe dropdown sits inside the top-left of each chart, with standard presets followed by Custom. Layout topology and chart configurations are saved per authenticated user and run through a revision-checked API contract. Blind runs use the same immutable data and replay lifecycle, but the browser renders local weekday/time labels and a stable normalized price scale without complete dates or raw prices.

Each chart pane follows its latest cursor-bounded candle by default. Horizontal navigation away from that candle detaches only the affected pane from follow, preserving its visible range while replay continues; a lower-right return-to-latest control and the existing time-axis double-click gesture restore follow. Follow state is derived from the pane's scroll position relative to its normal real-time offset and is not a second persisted workspace setting or replay cursor. It becomes active again if replay naturally catches the viewport up to that offset.

Filled positions are visible in the run's chart workspace through indicators derived from committed simulation state, not saved drawings. Every chart pane shows each open position's fixed entry line and active stop/target levels, remaining quantity, and unrealized USD P&L at the latest revealed close before hypothetical exit costs. Mark-to-market uses frozen instrument metadata and an as-of quote-to-USD rate; the value is display-only and does not change current balance or closed-trade analytics. Stop and target dragging, BE-to-entry, and X-to-close controls are scoped to one stable position id, so simultaneous positions retain independent protection and exit behavior. BE and X reuse the existing protection and manual-close operations, including their validation, activation, cost/FX, and OCO rules.

## Technical Context

**Language/Version**: Python 3.12; TypeScript 5.6; React 19.

**Primary Dependencies**: Flask 3.1.1, MongoDB, MinIO, the pinned `dukascopy-market-data` Python dependency (`fetch_instrument_codes` and its per-day download API), Pandas, PyArrow; CandleKit React bindings from @getcandlekit/charts 0.1.0 (0.1.1 is not published); lightweight-charts 5.x as required by CandleKit; a directly pinned `flexlayout-react` version satisfying CandleKit 0.1.0's optional `^0.9.1` workspace peer.

**Storage**: MongoDB for user-scoped Backtest run/account metadata (including immutable blind mode, normalized-price reference, $10,000 default starting balance, and 1% default risk percentage), durable selection/preparation jobs and leases, random year/date attempt checkpoints, per-UTC-date preparation checkpoints, replay position, bounded simulation control fields embedded on the run, versioned chart workspace documents with optimistic revisions, drawing documents, simulation operation-journal records, and the durable run-deleting cleanup marker. Separate run-scoped simulation order, fill, open-position, and cost-profile records avoid unbounded arrays on the run document. Closed simulated trades use the existing trade model under the run’s dedicated Backtest account; current balance derives from initial balance plus the committed net cash effect of fills, with each execution cost counted once, partial exits reflected as committed, and unrealized P&L excluded; required quote-to-USD conversion candles/rates are included in the immutable run snapshot. MinIO stores per-date preparation staging and immutable run-owned one-minute Parquet snapshots. CandleKit holds live chart/controller state in the browser; its serialized workspace topology is stored by JanusEdge, not browser local storage.

**Testing**: Backend pytest suite; frontend Vitest, ESLint, and TypeScript/Vite production build; focused API, random candidate selection, worker recovery, replay-adapter, synchronization, and browser scenarios described in quickstart.md.

**Target Platform**: Existing self-hosted web application; Flask API and React/Vite frontend in supported evergreen browsers.

**Project Type**: Full-stack web application.

**Performance Goals**: The specification sets playback at 1, 5, or 20 one-minute source candles per second. The user chose no fixed chart-tab maximum and no additional chart-tab capacity or rendering-performance target for v1. Use CandleKit’s incremental bar update for normal playback and rebuild cursor-bounded data after seek or step-back; avoid routing every candle through React component state. Serialize simulation operations without slowing ordinary chart rendering; no separate responsiveness guarantee is defined across an unbounded number of tabs.

**Constraints**: One instrument from the pinned downloader’s current supported catalog and one-minute source bars per run; manual replay selection remains capped at one calendar year, random duration is 1/3/6/12 calendar months, and both use a one-calendar-month warm-up request; UTC-aligned, left-closed/right-open chart buckets; no synthetic candles; no future replay-period bars rendered; pre-start context is not replayed; Real and Backtest data remain separate; authenticated resources are scoped to the requesting user. Blind mode is unchecked by default, immutable per run, forces random selection, and masks only rendered UI; its price reference is the first available replay-period candle open, with the exact requested ratio also used for negative references. Zero or non-finite references prevent readiness. Selection and preparation jobs and checkpoints must be durable across API and worker restarts. CandleKit’s current repository describes the package as early-stage, so pin versions and isolate it behind a JanusEdge adapter.

**Scale/Scope**: Per-user runs of up to one calendar year of selected replay-period candles plus up to one calendar month of warm-up candles; any number of persisted chart tabs per ready run, with one shared replay controller per open run; crosshair synchronization enabled by default and pane-local panning and zooming.

## Constitution Check

**Constitution status**: .specify/memory/constitution.md is still the Spec Kit placeholder template: its principles and gates contain bracketed placeholder text. It does not define ratified project rules, so this plan cannot honestly claim a pass or identify a constitution violation. The feature requirements below are used as the design gates until the project constitution is completed.

**Pre-design feature gates**:

- No-look-ahead: chart data is derived from the immutable run snapshot only through the shared replay cursor.
- Workspace isolation: every run, account, candle read, replay-position write, and drawing read/write is scoped to the authenticated user and Backtest mode.
- Run immutability: refreshed market data cannot replace the snapshot already assigned to a ready run.
- Time correctness: source instants stay UTC; interval membership uses fixed UTC boundaries; display timezone affects formatting only. The context start is calculated as a local calendar date before UTC conversion, separately from the selected replay boundary.
- CandleKit boundary: the React/chart adapter isolates version-specific library APIs and style overrides.
- Workspace integrity: one versioned layout per authenticated user and run, unique stable chart ids, valid intervals and split dimensions, and at least one chart panel after every accepted write.
- Follow integrity: a following pane tracks only its latest replay-revealed chart candle; a pane navigated away from that edge retains its own range, with state evaluated independently per pane.
- Deletion integrity: only an authenticated owner's run and its dedicated Backtest account, linked trades, and run-owned data may be removed; pending deletion fences preparation/replay writes and resumes safely after restart.
- Selection integrity: capture the local-yesterday cutoff once; persist the bounded year/date attempt state; a provider error is not an empty day; deletion fences an active selection before account creation.
- Blind display integrity: a blind run is always randomly selected; its rendered views reveal no complete calendar dates or raw prices, use its immutable price reference across all chart panes, and retain the underlying values for normal replay calculations.
- Simulation causality: all orders, fills, stops/targets, costs, protection edits, and cursor movement are derived in deterministic source-candle order from the run’s immutable snapshot; a market entry fills only at the next available unrevealed candle open, limit entries and take-profit limits fill at their exact submitted prices only when an eligible future candle's range reaches them, and no candle’s range is used before that candle is processed.
- Simulation durability: an accepted mutation has one run-scoped sequence/operation identity, survives retry/restart without duplicate effects, and is fenced against conflicting order/cursor/reset operations. Closed trades are recorded once; complete runs remain inspectable and can be reset or deleted.
- Forex accounting: each closed trade retains native quote-currency P&L and applies the timestamp-appropriate quote-to-USD rate for USD analytics and initial risk; missing conversion data fails closed rather than silently substituting a scalar or 1.0 rate.

**Post-design check**: The proposed model and contracts preserve each feature gate. Random selection has an explicit pending state and creates no account until a start date is found; its start-day candle check does not replace selected-period coverage or readiness rules. Warm-up candles precede the replay cursor and may be shown only as historical chart context; the selected period alone controls readiness, playback boundaries, progress, and completion. Follow remains a per-pane view concern and moves only within cursor-bounded data, so it does not change the replay cursor or workspace API. Run deletion uses a durable owner-scoped state as both its cancellation fence and cleanup marker; cleanup is restricted to the dedicated run account and its linked trades. Implementation must verify package compatibility and the chart adapter against the locked dependency artifacts before building feature flows. The user resolved the drawing-visibility and capacity questions: preserve replay-aware drawing behavior if present in the pinned CandleKit artifact; otherwise use anchor-only visibility, with no creation/edit-time history, and impose no additional tab cap or performance SLA (checklist CHK006 and CHK020). Anchor-only visibility means a drawing created later but anchored entirely in the past may remain visible after rewind; this is an accepted v1 trade-off.

**Simulation gate evaluation**: All order acceptance and forward cursor movement pass through the same run-level compare-and-swap sequence. Market orders wait for the next available unrevealed candle and fill at its open; forward jumps process intervening source candles, and a new bracket cannot inspect its fill candle. Open exposure stays outside closed-trade views; only fully closed trades with a committed operation sequence and current reset generation become visible in the Backtest account. Costs are frozen per fill, FX conversion comes from immutable timestamped run data, and missing as-of conversion values fail closed. Final-candle processing closes exposure and retains a read-only `complete` run that can be reset or deleted.

## Architecture and Data Flow

1. The authenticated run-creation request validates the instrument against the current catalog exposed by the pinned downloader (`fetch_instrument_codes`) and validates the display timezone. Manual requests retain their existing date validation and create a preparing run, account, and durable job. Random requests validate `period_selection: "random"` and `period_months: 1 | 3 | 6 | 12`, capture local yesterday once, and create a `selecting_period` run and a durable selection job without dates or an account; both return 202. Blind requests add `blind_mode: true`, require random selection, and persist the flag. Requests without the flag retain the existing manual and random wire shapes. `GET /api/backtest/instruments` supplies the same catalog to the run form. If the catalog cannot be fetched, the API returns a service error and creates no run or account.
2. A separate worker process claims selection/preparation jobs using atomic MongoDB leases. Random selection computes its maximum eligible local start date from the fixed cutoff, randomly removes eligible years and probes at most ten distinct random dates per year without replacement. Each candidate probe fetches the UTC day or days intersecting that local calendar day and accepts only a COMB one-minute candle within the exact local-day UTC bounds; provider errors are terminal failures. It persists the pending candidate and completed empty attempts for recovery. A hit persists final dates and transitions into normal preparation, creates the one account using FR-009's label rules, and prepares the preceding warm-up month through the inclusive selected end. The worker processes each UTC date in the preparation interval through the downloader’s per-day API, writes non-empty candle data to a run-scoped MinIO staging prefix, and records date outcomes, completed-date checkpoints, and public progress in MongoDB. If a worker stops, its lease expires and another worker resumes the selection state or latest completed UTC date. After all dates complete, the worker assembles the final immutable Parquet snapshot, calculates selected-period coverage and optional warm-up coverage, and determines the first snapshot index at or after the selected replay start. Only if a candle exists in the selected replay period does one MongoDB run-document update set ready status and persist the initial cursor at that index and timestamp. A no-data or terminal failure creates the dismissible user-scoped notice, deletes the run/account/job, and cleans up staging. The existing tick-derived /market-data/ohlc store is not the source for these runs.
- For forex symbols with a non-USD quote currency, the preparation path resolves a supported direct or inverse USD conversion instrument from the pinned catalog, downloads and checkpoints its one-minute history alongside the traded symbol, and pins it inside the same immutable run artifact. USD-quoted pairs require no extra series and use rate 1. This makes each entry/exit conversion reproducible from the run snapshot; fail an affected trade operation when there is no conversion observation at or before its event timestamp.
3. One CandleKit replay controller per run reads the immutable snapshot through a ReplayDataSource adapter. CandleKit ReplayControls submit step/play/forward-seek targets through a JanusEdge transport adapter to the authoritative simulation advance endpoint; visible cursor and chart bars update only after the server commits and returns the new position. Backward movement uses the guarded replay-position endpoint and is refused after an order until reset. If CandleKit does not offer the required 1x, 5x, and 20x choices, a JanusEdge-styled wrapper supplies only the missing speed selector and binds it to the same controller. Never allow the browser replay source to reveal future candles while an advance request is pending.
4. `BacktestChartWorkspace` creates one CandleKit workspace, registers a custom JanusEdge chart panel wrapping the existing Backtest chart adapter, and composes `WorkspaceProvider` with `FlexLayoutAdapter`. A new run uses `buildSingleChartLayout()` with one 1m chart. An accessible `+` button in the tab row creates and activates a chart tab in the focused tab group; no separate toolbar or drag-instruction row is shown. Reordering changes that group order; dropping an existing tab at a pane edge moves the same tab into a horizontal or vertical split, and splitters resize panes. Closing the focused tab is allowed only while another chart tab remains. Do not substitute the example's generic `ChartPanel` or `ReplayPanel`; the latter is not present in pinned 0.1.0. The workspace may have any number of chart tabs.
5. Each chart panel owns a CandleKit ChartView and its selected interval. A compact, chart-styled timeframe dropdown is overlaid inside the upper-left chart area and offers the standard 1m, 5m, 15m, 30m, 1h, 4h, and 1d choices, followed by Custom. Selecting Custom opens a popup for an integer-minute interval from 1 to 1,440; after applying it, the selected interval label (such as 7m) appears directly in the dropdown. Do not render a separate chart title, visible volume explanation, or numeric interval header; preserve the quoted-liquidity meaning in accessible chart text. A versioned per-user/run layout document stores the serializable workspace tree (splits, orientation, weights, tab groups/order, and active tab) plus stable chart ids and panel configurations. Implement CandleKit's `LayoutPersistence` interface over authenticated `GET`/`PUT /api/backtest/runs/{run_id}/chart-workspace`, with expected revisions; debounce/coalesce saves and serialize them. Use the authenticated API as source of truth, never CandleKit's sample LocalStoragePersistence. Validate ownership, supported schema and panel types, unique chart ids, valid intervals, positive split weights, and at least one chart. For new runs, initialize one stable-id 1m pane before mounting/enabling workspace interaction. For existing flat tab documents without a layout, migrate all records in position order to visible sibling panes, preserving ids and intervals; the old schema has no topology or sizing to preserve. Write the migrated version with compare-and-swap so concurrent page opens cannot replace a newer layout. Bootstrap conflicts reload the winning initialization; an edit conflict returns 409, preserves the unsaved draft, and offers reload or explicit reapply after review rather than silently retrying stale state.
6. Every chart adapter emits only the aggregate bar built from source candles seen through the current cursor. Forward playback uses incremental chart updates; seeking and stepping backward rebuild visible bars from the cursor-bounded source. All panels remain attached to the single run replay controller.
7. CandleKit’s SyncEngine routes crosshair synchronization. A JanusEdge adapter maps crosshair positions through UTC time before applying them to charts with different interval widths. A crosshair with no exact target candle snaps to the nearest available candle at or before the source time. Do not synchronize horizontal visible ranges: pan and zoom stay local to each pane.
8. Each chart panel’s CandleKit DrawingController owns its live drawing model and exposes the standard drawing tools for create, select, reposition, edit, and remove. The app loads and saves DrawingEngine export/import payloads through authenticated, run- and timeframe-scoped API routes. Inspect the pinned CandleKit artifact for replay-aware drawing visibility and preserve that behavior if present; otherwise hide a drawing while any time anchor is beyond the replay cursor and show it again once all anchors are at or before the cursor. The fallback does not use creation/edit time or alter the saved drawing state; consequently, a later-created drawing anchored in the past may remain visible after rewind. Edits and removals are persisted. A panel move may unmount its component: flush pending drawing writes and unregister replay/sync listeners before registering the same stable chart id in its new location.
9. ThemeContext selects CandleKit’s light/dark theme. Scoped CSS overrides and the chart theme palette map CandleKit controls and overlays to JanusEdge’s Tailwind gray, brand, profit, and loss colors.
10. Each chart pane starts at the latest candle exposed by its replay cursor. A panel-scoped follow coordinator observes the pane's scroll position relative to its normal real-time offset and the latest revealed chart bar. While that pane is snapped to the real-time edge, replay data updates keep it there; time-axis pan away from that edge suspends auto-scroll for that pane. Use a non-animated, coalesced reposition for continuous replay updates so 20x playback does not repeatedly restart `scrollToRealTime()` animations; use the animated real-time scroll for initial snap, the return button, and the existing equivalent double-click gesture. Each pane evaluates follow from its own viewport; panning or zooming one pane does not change another. In-place updates to a higher-timeframe active candle do not change its horizontal scale or range.
11. Run deletion is confirmed in the run list and accepts selecting-period, preparing, ready, and complete runs. The authenticated API durably moves an owned run to `deleting`; this state immediately makes it non-playable and excludes its account and linked trades from Backtest views. The preparation worker treats the run state as a cancellation fence, so a leased selection cannot create an account and a leased preparation cannot publish a ready snapshot after deletion begins. The worker scans deleting runs after restart and idempotently removes staged and immutable MinIO objects, preparation jobs, all run-scoped simulation control/operation/order/fill/position/cost records, every run-tagged Execution whether or not it has a Trade link, all trades linked through the run's dedicated account (using the existing trade-owned-data cleanup), the account, replay cursor, chart tabs/workspace, and drawings; it removes the run record only after dependent cleanup succeeds. Repeated delete requests while cleanup is pending return the same pending state. Real records and resources belonging to other runs are never part of the deletion scope.
12. Blind mode is persisted on the run and cannot be toggled after creation. The form forces and locks random selection while Blind mode is checked; the 1, 3, 6, or 12 month duration remains selectable. Run-list, detail, coverage, notice, deletion-dialog, and account surfaces omit complete dates; both blind account name and display label contain the instrument and “blind” but no date. The chart adapter derives or reads the fixed reference from the first available replay-period candle open and applies `100 × P / referencePrice` to all displayed OHLC and price-coordinate values, including warm-up context and drawings. For negative references, reorder transformed high/low values while preserving directly transformed open/close. Displayed replay cursor timestamps, date ticks, and crosshair text show local weekday/time in the configured display timezone. Browser rendering hides values, but raw dates/prices remain in storage and API responses. If the reference is zero or non-finite, the worker must fail the run before readiness through the existing cleanup/notice lifecycle; negative references follow the specified ratio despite reversing price direction. Closed simulated trades linked to blind runs inherit the run’s privacy mode in Journal, showing weekday/time and normalized entry/exit values without complete dates or raw prices.
13. A Backtest simulation service owns order validation, causal candle processing, FX conversion, costs, and close-trade publication. Bounded CAS control fields on the BacktestRun serialize operations and atomically store sequence, cursor/index, reset generation, backward-navigation lock, and completion state; each client command has an idempotent operation id. Full operation results and order/fill/position effects use deterministic identifiers and are visible only through the last committed sequence. Store order, position, and cost-profile projections as versioned records, preserving the last committed version while new effects are staged; fills remain append-only. Persist operation intent/effects before advancing the run sequence so MongoDB standalone deployments can resume an interrupted action without multi-document transactions. Keep operation, order, position, and cost-profile records in dedicated collections; represent each allocation fill as a run-tagged existing Execution document rather than growing arrays on the run document. Reset atomically increments generation and rewinds the cursor so old state is immediately hidden, then idempotently purges that generation while its operation gate blocks new writes; retain operation-key results for retries and preserve the run's cost profile. On run deletion, include every simulation collection and the Backtest trade cascade in the existing durable cleanup.
14. A single server-side candle processor advances through every available one-minute source candle between the committed cursor and a requested target; forward seeks may not skip simulated triggers. Existing protective orders are evaluated before later candle entries, and an entry’s SL/TP cannot inspect its fill candle. When a run reaches the final replay-period candle, process eligible orders, cancel still-pending entry orders, force-close open positions at that candle’s close with configured costs, and persist `complete`. Completed runs allow inspection, reset, and deletion, but reject new orders and cursor movement. After the first accepted simulated order, backward step/seek is disabled until an explicit confirmed reset.

## Design Decisions

- Use CandleKit’s React entry for chart views, ReplayControls, and the standard drawing toolbar. ReplayControls remain the transport UI, but their actions pass through a JanusEdge adapter that requests server-side candle processing and only then synchronizes the shared CandleKit controller and all panes to the committed cursor. If ReplayControls cannot expose the exact 1x, 5x, and 20x choices, wrap or extend only the speed selector with JanusEdge-styled React presentation. Do not replace play, pause, stepping, or seek with a second custom transport UI, and do not build a second chart, replay, synchronization, or drawing engine.
- Pin CandleKit to 0.1.0 because the requested 0.1.1 is not published, and lock a single Lightweight Charts 5.x version. The 0.1.0 artifact was inspected and exports the required React, replay, sync, and drawing APIs. `ReplayControls` accepts a speed list, and its drawing API has no replay-aware visibility behavior, so pass `[1, 5, 20]` and use the specified anchor-only visibility fallback.
- Use one ReplayController for the run, not one replay instance per tab. Persist the cursor on the run record, restore it on page open, and serialize and version cursor writes so stale requests cannot overwrite a later selected position, including an intentional step-back.
- Use CandleKit's workspace API through `FlexLayoutAdapter`, with a custom JanusEdge chart panel. Pin `flexlayout-react` directly to an exact version satisfying CandleKit 0.1.0's optional `^0.9.1` peer; the peer is not currently installed. The linked workspace example demonstrates the intended composition, but its current-branch `ReplayPanel` is not exported by pinned 0.1.0 and must not be copied into the implementation.
- Use the run's durable `deleting` lifecycle state as a temporary cleanup marker instead of introducing an independent deletion queue. Return an accepted/pending result once the owner-scoped state transition is stored; this response and interim hiding do not mean deletion is complete. Make the existing worker reclaim deleting runs and repeat every cleanup step safely. Use the existing trade deletion cascade to physically remove every linked trade and all trade-owned records or files. Physically remove every object under the run's MinIO prefix, including staged, immutable snapshot, and unreferenced/orphaned objects; verify the prefix is empty. Include all simulation control, operation, order, fill, position, event, and cost data in the purge. Only after all run-owned MongoDB records, account/trades and dependents, and MinIO objects are gone, remove the run record that carries the deletion marker. Never cascade by account label or user-wide Backtest scope.
- Add `complete` as a retained run state. Completion is an explicit final-candle transition after pending entries are canceled and remaining exposure is closed at the final candle close with costs. A completed run remains read-only and inspectable; reset is an explicit confirmed operation that clears that run’s simulated activity and rewinds to the first eligible replay candle, while keeping per-run cost configuration.
- Use bounded simulation control fields on BacktestRun with optimistic compare-and-swap plus a monotonically increasing committed sequence. Mutating operations carry a client operation id unique within user/run; retries return the prior result. Since the shipped Compose MongoDB is standalone, do not rely on multi-document transactions: reserve the operation on the run, persist deterministic effects/journal state, and publish them by advancing the committed sequence. Recovery resumes a pending operation. Operation, order, position, and cost-profile records live in dedicated collections; fill allocations extend the existing Execution collection, with no unbounded run-document arrays.
- Extend the existing worker's recovery scan to claim/resume any run with a pending simulation operation after restart. Deterministic ids and unique operation keys make re-applying already persisted effects safe; the run's committed sequence gates both simulation readers and linked Trade analytics during recovery.
- Route all simulation commands and candle advancement through one ordered gate. A next-candle market order submitted after candle N waits for the next available source candle index and fills at its open; gaps do not generate synthetic bars. A forward jump processes each intervening candle.
